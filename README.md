# Space Game — Lab 01 & Lab 02

## Опис проєкту
Мультиплеєрна браузерна гра в реальному часі (клієнтська частина на Vite + Vanilla JS), реалізована за стандартом фіксованого кроку симуляції (*Fix Your Timestep*) та об'єктно-орієнтованої моделі сутностей на базі класів ES6 та колекції `Map`.


## Звіт з експериментів (Lab 01)
1. **Блокуючий цикл (Busy-wait у кадрі):** 
   - *Експеримент:* Додавання синхронного циклу `while` на кілька секунд усередину кадру зупиняє роботу браузера.
   - *Пояснення через Event Loop:* Оскільки JavaScript виконується в один потік (*Single-threaded, Call Stack*), виконання важких синхронних операцій повністю блокує потік. Event Loop не може дістатися ні до подій рендерингу (`paint`), ні до таймерів, доки стек повністю не звільниться.
2. **`setInterval` проти `requestAnimationFrame`:**
   - `setInterval(fn, 16)` не гарантує синхронізацію з частотою оновлення монітора (герцовкою), що призводить до мікроривків (*jank*). `requestAnimationFrame` синхронізований із перемальовуванням вікна браузера.


##  Архітектура та вибір підходів (Lab 02)
1. **Композиція замість глибокого успадкування:**
   - Замість занадто глибоких ієрархій на кшталт `Entity -> Moving -> Ship -> Player`, використано плоску структуру з композицією та унікальними сутностями. Це захищає від крихкості базового класу при додаванні нових модулів (наприклад, кулі-самонаводжувачі або об'єкти підбору `pickup`).
2. **Використання `Map` для менеджеру сутностей:**
   - Колекція `Map` була обрана замість звичайного об'єкта `{}` як словника, оскільки вона оптимізована для частих операцій додавання та видалення (`set`, `delete`, ітерація через `for...of`), а також гарантує збереження порядку ключів та уникнення конфліктів із прототипами.
3. **Фікс контексту `this`:**
   - Використання стрілочних функцій для методів на кшталт `fire = () => {}` гарантує правильний контекст `this` незалежно від того, як саме викликається колбек.

   # Space Game — Lab 03: Asynchronous JavaScript & Loading Pipeline

## Що зроблено в Lab 03
1. **Асинхронний пайлайн асетів (`src/assets/loader.js`):**
   - Завантаження спратів і ресурсів реалізовано паралельно через `Promise.all`.
   - Додано функцію повтору з експоненційним згладжуванням та рандомізацією (*retry with exponential backoff + jitter*) для обробки тимчасових мережевих збоїв.
   - Повністю підтримується `AbortSignal` для скасування неактивних запитів.
2. **Екран завантаження:**
   - На холсті реалізовано реальний прогрес-бар (`0% - 100%`), який оновлюється під час завантаження кожного асета.
3. **Архітектурна розв'язка (Decoupling):**
   - Ігрова симуляція відокремлена від модулів інтерфейсу та допоміжних систем через шину подій на базі `EventTarget` / `CustomEvent`.


## Головоломки порядку мікрозадач (Microtask Ordering Puzzles)

1. **Головоломка 1 (Базовий порядок microtask):**
   ```javascript
   Promise.resolve(1).then(console.log);
   console.log(2);
   ```
   

2. **Головоломка 2 (Комбінація setTimeout та Promise):**
```javascript
setTimeout(() => console.log('timeout'), 0);
Promise.resolve().then(() => console.log('promise'));
console.log('sync');
```

3. **Головоломка 3 (Ланцюжки async/await та await null):**
```javascript
async function f() {
  console.log(1);
  await null;
  console.log(2);
}
f();
console.log(3);
```

4. **Головоломка 4 (Вкладені мікрозадачі):**
```javascript
Promise.resolve().then(() => {
  console.log(1);
  Promise.resolve().then(() => console.log(2));
});
console.log(3);
```

5. **Головоломка 5 (Порядок таймерів та мікрозадач усередині колбеків):**
```javascript
setTimeout(() => {
  console.log('timer');
  Promise.resolve().then(() => console.log('micro inside timer'));
}, 0);
```
